
## Урок 10 (ночь 21-22.11). Entware-деплой и Reality-туннель — полный разбор
1. **Загрузка файлов в том (том Netcraze)**: RCI put (анонс) + POST **/fui** (БЕЗ слэша!).
   Слэш = 405. Перед POST создать каталог: `mkdir uuid:/path` (иначе 500).
   Большие файлы (>5МБ): нужен keepalive-поток put каждые ~2с, иначе 502.
   30МБ одним куском = смерть медленной флешки: качать ВНУТРЬ роутера через
   Entware curl --socks5-hostname (рабочий прокси) — 2МБ/с стабильно.
2. **NDMS CLI**: `ls` = максимум ~10 записей; `more` = файлы до ~几百KB,
   бинарники отказом; корневые файлы `more uuid:/файл` = parse error
   (копировать в подкаталог). `copy` = только между локальными томами.
3. **Синтаксис drift**: KeeneticOS 5.1.8 (`wireguard private-key`) vs
   Netcraze 5.1.9 (`wireguard peer` = 44-симв. ключ С "="; private-key
   внутри `wireguard` контекста). Всегда запрашивать `?` в контексте!
4. **confdir xray = все *.json сливаются!** Тест-конфиги удалять сразу,
   иначе мердж-каша = мистические сбои роутинга.
5. **Reality "received real certificate"** = сервер отверг аутентификацию.
   Проверять: часы (±90с!), ключи (pbk/sid!), версию клиента vs сервера
   (26.10+ vs старый сервер несовместимы: у нас рабочий = yichya 26.9.9).
   Балансер leastPing выбирает "живой" канал с рабочей маскировкой —
   мёртвый upstream с сайт-прикрытием выглядит живым! Прямой outboundTag
   надёжнее балансера.
6. **Переадресация портов vs интерфейсные ACL**: ACL на WAN не открывает
   INPUT-порты Entware (только FORWARD). Доступ к socks/ssh Entware с WAN
   невозможен без REDIRECT на его стороне — используй туннель или LAN.
7. **Entware dropbear**: XKeen ставит на 222 (или переопределяй
   /opt/etc/config/dropbear.conf). Root-пароль = пароль роутера (XKeen)
   или keenetic (официальный установщик Entware).
8. **Doctor v2** (doctor2.py): проверяет WG-туннель, dropbear, xray,
   exit-IP через оба socks, MTU. Запускать после ЛЮБОГО изменения.
9. **Тест-инструменты**: все bash = с timeout; python -I; ugrep-алиас
   ломает сложные grep-пайпы — использовать python для обработки вывода.

## Рефлексия ночи 21-22.11 (шлюз подруги) — правила, оплаченные часами

### Мышление
1. **Топология раньше артефакта.** Прежде чем бисектировать версии/сборки:
   выпиши, чем РАБОЧИЙ случай отличается от нерабочего физически (путь
   пакета, NAT-уровни, источник). У нас: его xray = локальный вывод шлюза
   (работает), все внешние машины = транзит через его Keenetic (падает).
   Ответ (двойной NAT ломал Reality) проверяется за 15 минут — вместо
   6 часов бисекта.
2. **Если конфигурация когда-то работала — пересборка не лечит**
   перемежающийся сбой. Ищи, что изменилось в окружении (ребут, respawn
   демона, обновление правил), а не в артефакте.
3. **Самое простое объяснение ошибки — первым.** 500 при загрузке файла =
   сначала «существует ли каталог?», потом теории о «роутер отвергает
   бинарники».
4. **Интермитент = состояние, а не случайность.** «Работает через раз» =
   что-то в состоянии системы флипает (config-мердж, respawn демона,
   ротация ключей). Ловить состояние, а не повторять попытки.

### Исполнение
5. **confdir xray грузит ВСЕ *.json** — тест-конфиги удалять СРАЗУ после
   теста, иначе мердж отравит все последующие проверки (два ложных
   вывода: «coalagent виновен», «prox-reserve сломан»).
6. **sed для JSON на роутере — запрещено.** busybox sed не знает GNU-
   диапазоны; python3 на Entware нет. JSON-правки: готовить локально
   питоном (json.dump), заливать файлом целиком.
7. **Lockout-политика SSH** (5 попыток / 15 мин) — не долбить сессиями:
   длинные диагностики одним подключением; между подключениями пауза.
8. **Туннель умирает между bash-вызовами.** Всё, что требует туннеля,
   — одним атомарным вызовом: (туннель & ) + sleep + работа + чтение.
9. **NDMS `ls` = ~10 записей; `more` = малые текстовые файлы, refuses
   binaries, корневые файлы = parse error (копировать в подкаталог).**
10. **Двухуровневые маршруты = встроенный failover ядра:** основной
    через туннель (metric 10), запасной через WAN (metric 100). При
    падении туннеля ядро само переключает. Проще любого мониторинга.
